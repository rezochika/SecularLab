Delivered behavior

- Rational parsing validates mantissa grammar before decimal-point removal.
  Misplaced signs are rejected, including .-1, .+1 and -.-1 in plain and
  scientific notation; valid signed decimals, integers, p/q and e/E/d/D syntax
  remain supported. The core regression contains 59 assertions.
- Coefficient verification returns false for either matrix dimension mismatch
  before accessing the second matrix's data.
- Candidate certificate refinement adapts to close roots and their scale, and
  failed exact acceptance permits additional Graeffe separation within the
  configured resource budget. Exact inertia and rounding acceptance remain the
  certification gate. Recovery tests cover 1e-20 separation, tiny roots around
  1e-100, large roots around 1e100, combined tiny clusters, insufficient limits,
  and an exact scalar with output precision exceeding working precision.
- Native Windows Release/Debug builds use CLion's existing bundled MinGW plus
  project-local GMP C++ and Boost dependencies. Full application tests passed.

Sanitizer caveat

The initial default PIE ASAN+UBSAN run is recorded as failed: the recovery test
emitted repeated AddressSanitizer:DEADLYSIGNAL and hit its 180-second timeout.
The original temporary log reached 1,456,307,546 bytes. Only a bounded head/tail
excerpt is included here.

An independent int main(){return 0;} program with the same GCC sanitizers passed
25/30 default-PIE launches; five produced runaway diagnostics until a 1 MiB
per-child file cap terminated them with SIGXFSZ. The same toy built with
-fno-pie -no-pie passed 100/100 launches. A fresh project Debug build using those
flags only at configure time passed all five tests. This supports an
environment-dependent PIE sanitizer runtime startup problem; the precise
kernel/runtime cause was not established. No project CMake change was made to
apply these local sanitizer validation flags. Toy results, environment and
bounded initial failure evidence are included in logs/. The copied sanitizer
summary describes the first diagnostic passing run (0.96 s); the final
revalidation after the last solver refinement is separately recorded in
linux-sanitizer-final-ctest.log (0.86 s).

Limits

The upstream GMP full test suite was not run. The Windows GMP C library was
reused from CLion; its matching C++ wrapper was built locally and smoke-tested,
then exercised by all application tests. Separate certificate replay shares
the application's exact-inertia implementation, so it is not an independently
authored proof checker. This repair record contains no new SciPy/mpmath solve,
Windows sanitizer run or macOS build. The single oilrig timing is not a
controlled benchmark or a claim of speed superiority.
